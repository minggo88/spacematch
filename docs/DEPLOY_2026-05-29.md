## 2. F&B HTML 다중 인코딩 수정

**증상:** 공간 상세 모달에서 "F&B" 텍스트가 "F&amp;amp;amp;amp;amp;B" 형태로 표시됨  
**원인:** PHP 저장 시 `htmlspecialchars()` 적용으로 `&` → `&amp;` 변환. 재저장할 때마다 중첩 인코딩 누적. React는 plain text 렌더링이라 디코딩 없이 그대로 출력  
**조치:**
- 저장 엔드포인트: `htmlspecialchars()` 제거, `strip_tags()` 유지 (PDO가 SQL injection 방어)
- 조회 엔드포인트: `deep_decode()` 헬퍼 추가, 기존 누적 인코딩 데이터 복원  

**파일 (PHP — FTP 배포):**
- `public/api/venues/add_venue.php`
- `public/api/venues/update_venue.php`
- `public/api/venues/get_venues.php`
- `public/api/venues/get_my_venues.php`
- `public/api/venues/get_all_venues_admin.php`
- `public/api/venues/get_pending_venues.php`

**배포:** `www/api/venues/` 에 위 6개 파일 FTP 업로드

## 5. 어드민 → 호스트 채팅 기록 미저장·수신 불가 수정

**증상:** `/admin/hosts`에서 채팅하기 버튼 클릭 시 채팅 화면은 열리지만 기록이 남지 않고 상대방도 메시지를 수령하지 못함  
**원인:** `ChatPage.jsx`에서 admin은 `?type=cs`로만 대화 목록을 조회하는데, `createConversation` 호출 시 `type`을 명시하지 않아 대화방이 `type=direct`로 생성됨. `direct` 방은 admin의 CS 목록에 조회되지 않으므로 페이지 이동 후 기록이 사라지고, 알림/메시지 흐름도 어긋남  
**조치:** admin이 대화 생성 시 `type: 'cs'`를 명시적으로 전달 → CS 목록에 정상 노출, 상대방 알림 정상 발송  
**파일:** `src/pages/ChatPage.jsx`  
**배포:** `npm run build` → `www/index.html` + `www/assets/` 업로드
