## 채팅 이미지 전송 수정

### 증상
채팅 팝업(우측 하단 floating 버튼)에서 이미지 업로드 시 발신자·수신자 모두 이미지가 보이지 않음.

### 원인
`public/api/chat/upload.php`의 파일 저장 경로 버그:

```php
// 버그: dirname(__DIR__) = public/api/
$uploadDir = dirname(__DIR__) . '/uploads/chat/';
// 파일 저장: public/api/uploads/chat/[file]
// URL 반환:  /uploads/chat/[file]  →  public/uploads/chat/[file]  (불일치! 404)
```

저장되는 물리 경로(`public/api/uploads/chat/`)와 브라우저가 요청하는 URL(`/uploads/chat/`)이 다른 디렉토리를 가리켜서 이미지가 항상 404.

추가로 업로드 실패 시 사용자에게 에러 메시지가 표시되지 않았음.

### 조치

| 파일 | 변경 내용 |
|------|-----------|
| `public/api/chat/upload.php` | `dirname(__DIR__)` → `dirname(dirname(__DIR__))` 로 수정 (저장 경로를 `public/uploads/chat/`으로 정정). mkdir 실패 시 에러 응답 추가. |
| `src/pages/ChatPage.jsx` | 업로드 실패 시 `alert`으로 에러 메시지 표시 추가. |

수정 후 경로:
```
저장: public/uploads/chat/chat_xxx_yyy.jpg
URL:  /uploads/chat/chat_xxx_yyy.jpg  → public/uploads/chat/chat_xxx_yyy.jpg  ✓
```

`.htaccess`의 `RewriteCond %{REQUEST_FILENAME} !-f` 규칙에 의해 실제 파일은 SPA 라우팅 우회 없이 정적 파일로 직접 서빙됨.

### 배포 경로

1. **PHP** (필수): `public/api/chat/upload.php` → `www/api/chat/upload.php` FTP 업로드
2. **React 빌드** (필수): `npm run build` 후 `www/index.html` + `www/assets/` 업로드
3. **서버 디렉토리** (최초 1회): `www/uploads/chat/` 디렉토리 생성 + 쓰기 권한(755) 부여
   - PHP `mkdir()`이 자동 생성하지만, 서버 권한에 따라 수동 생성이 필요할 수 있음

## 호스트 거절 사유 셀러에게 표시 수정

### 증상
호스트가 셀러 입점 신청을 거절할 때 거절 사유를 입력해도, 셀러의 신청 현황 페이지(`/seller/applications`)에서 거절 사유가 전혀 표시되지 않음.

### 원인 분석

| 레이어 | 상태 | 비고 |
|--------|------|------|
| DB 저장 (`update_status.php`) | ✅ 정상 | `rejection_reason` 컬럼에 저장됨 |
| API 응답 (`get_applications.php`) | ✅ 정상 | `SELECT a.*`에 `rejection_reason` 포함 |
| **셀러 렌더링** (`SellerApplications.jsx`) | ❌ **누락** | `rejection_reason` 표시 코드 없음 |

호스트 측(`HostApplications.jsx`)에는 `rejection_reason`을 표시하는 코드가 있으나, 셀러 측에는 해당 코드가 없었음.

구독 플랜 블러 처리는 **호스트**가 신청자(셀러) 상세 정보를 보는 영역(`priority_viewing` 구독)에만 적용됨. 셀러가 자신의 거절 사유를 보는 것은 구독 제한 대상이 아님.

### 조치

| 파일 | 변경 내용 |
|------|-----------|
| `src/pages/seller/SellerApplications.jsx` | 거절(rejected) 카드에 `rejection_reason` 표시 배너 추가 |
| `public/locales/ko/seller.json` 外 10개 | `appPage.rejectionReason` 키 추가 (11개 언어) |

### 표시 조건
```jsx
{app.status === 'rejected' && app.rejection_reason && (
    // 거절 사유 배너 표시
)}
```
- `status === 'rejected'` AND `rejection_reason`에 내용이 있을 때만 표시
- 구독 제한 없음 (셀러는 항상 자신의 거절 사유 확인 가능)

### 배포 경로

1. **React 빌드** (필수): `npm run build` 후 `www/index.html` + `www/assets/` 업로드
2. **로케일 파일** (필수): `public/locales/*/seller.json` → `www/locales/*/seller.json` 업로드 (11개 파일)

## 호스트 셀러 상세 정보 열람 권한 버그 수정 (2차 — 카테고리 불일치)

### 증상
Premium 플랜 구독 호스트(ajincopor@gmail.com)임에도 `/host/applications`에서 셀러 상세 정보 패널이 항상 블러/잠금 처리됨.

### 원인 (2단계 버그)

**1차 버그 (이전 수정 완료):** 응답 파싱 오류
```
API 응답: { success: true, subscription: { active: true } }
코드:     d.active  →  undefined  (블러 해제 안 됨)
수정:     d.subscription?.active
```

**2차 버그 (금번 수정):** 프론트엔드가 조회하는 카테고리 `'priority_viewing'`이 DB에 존재하지 않음

Admin 패널에서 플랜을 만들 때 사용하는 표준 카테고리:
- `'입점 서비스'` / `'마케팅 서비스'` / `'프리미엄 서비스'`

아진 계정의 Premium 플랜은 `category = '프리미엄 서비스'`로 저장되어 있으나,
`check_subscription.php`에 `category=priority_viewing`으로 조회하므로 항상 `active: false` 반환.

### 조치

| 파일 | 변경 내용 |
|------|-----------|
| `public/api/payments/check_subscription.php` | `priority_viewing` 조회 시 결과가 없으면 `'프리미엄 서비스'`로 폴백 추가 |
| `src/pages/host/HostApplications.jsx` | 구독 체크 결과 `console.log` 추가 (진단용) |

```php
// category=priority_viewing으로 조회 후 없으면 '프리미엄 서비스' 재조회
if (!$sub && $category === 'priority_viewing') {
    $sub = hasActiveSubscription($conn, $userId, '프리미엄 서비스');
}
```

### 호환성
- DB에 `priority_viewing` 카테고리 플랜이 있으면 그것을 우선 사용 (기존 동작 유지)
- DB에 없으면 표준 `'프리미엄 서비스'` 플랜으로 폴백 → 아진 계정 정상 작동
- 다른 카테고리 조회에는 영향 없음

### 배포 경로

1. **React 빌드** (필수): `npm run build` 후 `www/index.html` + `www/assets/` 업로드
2. **PHP 변경 없음**
