# Deploy — 2026-06-04

## 1. HTML 엔티티(&#039; &amp; 등) 전면 수정

**증상:** 사용자 이름, 설명, 커뮤니티 게시글/댓글 등에 `&#039;`, `&amp;` 같은 HTML 엔티티가 그대로 표시됨

**원인:**
- 쓰기 API들이 DB 저장 전 `htmlspecialchars()`를 적용 → 엔티티가 DB에 저장됨
- 읽기 API 대부분이 디코딩 없이 JSON 반환 → 프론트엔드에 엔티티 노출
- venues API만 예외적으로 `deep_decode()` 함수를 local 정의해 사용

**조치:**
1. `db_connect.php`에 전역 헬퍼 함수 3개 추가: `deep_decode()`, `decode_fields()`, `decode_rows()`
2. 쓰기 API에서 `htmlspecialchars()` 제거 (PDO prepared statements로 SQL injection 방지 충분)
   - `auth/register.php`
   - `users/update_profile.php`
   - `community/community_posts.php` (POST)
   - `community/community_comments.php` (POST)
3. 읽기 API에 `decode_fields()` 적용 (기존 DB 엔티티 데이터 복원)
   - `users/get_users.php`, `get_user_detail.php`, `browse_hosts.php`, `browse_sellers.php`, `get_public_profile.php`, `get_host_public.php`, `update_profile.php` (응답)
   - `applications/get_applications.php`
   - `chat/conversations.php`
   - `community/community_posts.php`, `community_comments.php` (GET)
4. venues API 3개 (`get_my_venues.php`, `get_all_venues_admin.php`, `get_pending_venues.php`)에서 중복 local `deep_decode()` 제거 → db_connect.php 전역 함수 사용

**파일:** `public/api/` + `dist/api/` 34개 파일

**배포:** PHP only → `www/api/` FTP 업로드
