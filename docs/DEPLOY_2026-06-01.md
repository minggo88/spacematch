## 1. /admin/users/:id 입점 신청 내역 미표시 수정

**증상:** `/admin/users/23` 등 유저 상세 페이지에서 입점 신청 내역이 보이지 않음  
**원인:**
- PHP(`get_user_detail.php`): `role === 'seller'`일 때만 applications 쿼리 실행 → 다른 role(vendor 등)이면 빈 배열 반환
- React(`AdminUserDetail.jsx`): `user.role === 'seller' && applications.length > 0` 조건 → seller 외 역할은 렌더링 자체 불가  

**조치:**
- PHP: 조건을 `!in_array(role, ['host','admin','superadmin'])`으로 변경 → seller·vendor 등 모든 비호스트 역할에서 신청 내역 조회
- React: 조건을 `applications.length > 0`으로 단순화, 헤더 타이틀도 role 무관하게 '입점 신청 내역' 표시

**추가 수정 (2차):** `else if` 체인 구조 → host는 venues 조회 후 applications도 역할 무관하게 항상 조회로 변경

**파일:**
- `public/api/users/get_user_detail.php` → FTP `www/api/users/` 업로드
- `src/pages/admin/AdminUserDetail.jsx` → `npm run build` 후 배포

## 4. 채팅 메시지 중복 전송 버그 수정

**증상:** 텍스트/파일 메시지가 2개 이상 중복으로 표시됨  
**원인:** 폴링(2초 간격)과 메시지 전송 응답 사이의 race condition  
- 전송 fetch 대기 중(`lastMsgIdRef=5`) 폴링이 `after_id=5`로 요청 → 서버에서 새 메시지(id=6) 수신 → state에 추가  
- 이후 전송 응답 도착 → 동일 id=6을 state에 또 추가 → **중복**  
- 파일 업로드(`handleFileUpload`)도 동일 패턴  

**조치:** `src/pages/ChatPage.jsx` 3곳에 dedup 체크 추가  
1. `fetchMessages` 폴링 merge 시: `existingIds` Set으로 필터링 후 신규 항목만 append  
2. `handleSend` 완료 시: 동일 id가 이미 state에 있으면 추가하지 않음  
3. `handleFileUpload` 완료 시: 동일 id가 이미 state에 있으면 추가하지 않음  

**파일:** `src/pages/ChatPage.jsx`  
**배포:** `npm run build` → `www/index.html` + `www/assets/` 업로드
